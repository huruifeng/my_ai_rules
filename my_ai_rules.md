# DOs
* Format: each row can have around 120 characters.
* Prefer top-down scripts: For data processing, exploratory analysis, and scientific computing, use sequential, step-by-step scripts rather than wrapping the entire workflow in functions.
* Use functions selectively: Define helper functions when they improve readability, reduce meaningful duplication, or encapsulate reusable logic.
* Readability first: Write clear, self-explanatory code with meaningful variable names.
* Minimal comments: Add comments only when they explain non-obvious logic, assumptions, or important decisions.
* Keep analysis transparent: Organize code into clear stages, such as data loading, preprocessing, analysis, and visualization.
* Understand before coding: Review relevant existing code and requirements before making changes.
* Prefer the simplest working solution: Implement the minimum functionality required before considering enhancements.
* Validate relevant changes: Run focused tests or checks when feasible.
* Handle errors appropriately: Provide meaningful error messages without adding unnecessary defensive code.
* Separate suggestions from implementation: Optional improvements should be proposed, not automatically applied.
* Preserve reproducibility: For scientific analysis, use fixed random seeds when applicable and document important assumptions.


# DO NOTs
* Don’t “Slop Grenade”: Avoid generating huge volumes of low‑quality content just to fill space; shorter, focused outputs are better.
* Avoid large volumes of unnecessary explanations, repetitive content, or low-value code.
* Do not overengineer the codes until I ask you to do that, make codes sample and neat.Prefer simple, clean, and maintainable solutions over complex implementations.
* Do not commit and push the updates until I ask you to do that.
* Do not refactor unnecessarily: Suggest improvements separately rather than implementing them without permission.
* Avoid unnecessary output: Do not repeat large code blocks or lengthy explanations unless requested.
* Do not byond scope: Do not expand the task beyond what was requested.
* Avoid unnecessary introductions, repetitive summaries, or excessive Markdown formatting.
